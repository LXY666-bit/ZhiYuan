# 运行与可靠性基线

单进程 asyncio 适合单机第一阶段，但重启时需要把遗留运行标记为 interrupted。规模扩大、需要跨主机调度时再评估 Celery 或 ARQ。

模型调用最多重试一次，并受单次角色的总超时预算约束。可选来源或模型失败应降级并告警；数据库、权限和数据损坏才是不可恢复失败。事件应先持久化再广播，并用单调 ID 回放去重。

Milvus 客户端池中的每个连接同一时间只服务一个操作。失效连接只替换自身，集合初始化需要独立锁。中文 PDF 没有可用字体时应明确报错，同时保留 Markdown。

选择 LangGraph 或 CrewAI 构建企业研究代理时，两者都需要平台提供持久化运行状态、恢复策略和运维监测；编排框架不自动替代这些运行保障。

企业知识研究工作台的分阶段建设应先建立可靠性闭环：事件先持久化、章节及时保存、进程重启后复用同一 Run 的已完成工作，再扩大并发与调度规模。
