# 受监管企业 Agent 平台选型：验收约束

本资料是一次 live 研究验收的附件背景，不是关于任何开源框架能力的外部事实来源。

## 业务背景

一家受监管企业计划在 2026 年建设面向内部运营、合规审查和知识服务的 Agent 平台。首批场景包括：

1. 有审批、人工复核和可恢复状态的长流程；
2. 多角色协作的资料整理与报告撰写；
3. 通过 API 嵌入既有 Python 服务的轻量自动化。

## 不可妥协的验收条件

- 每次执行必须具备可恢复的状态、审计事件和明确的取消语义。
- 外部工具调用必须能经过权限控制；不能把模型文本当作授权。
- 结论必须区分“框架公开能力”“本企业集成成本”和“仍需 PoC 验证的假设”。
- 推荐不能只给出一个绝对赢家，应按场景、团队技能和治理要求给出条件化建议。

## 交付物要求

报告至少应包含执行摘要、约束映射、框架比较、风险/未知项和下一步 PoC。涉及框架行为的事实应优先引用官方文档或官方仓库，附件仅用于说明企业需求。
